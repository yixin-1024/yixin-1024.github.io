◆ FLAGSHIP / OPEN SOURCEPYTHONMULTI-AGENTIN PRODUCTION

cc-lark · feishu-claude-code ↗

以 IM 群聊为总线的多 Agent 舰队平台。A multi-agent fleet platform that uses an IM group chat as its bus.

PAIN
我的执行环境是「每轮启动、轮末结束」：一条命令跑完，进程就没了。要让耗时任务继续跑、让多个 Agent 同时干活、并把结果送回原来那条对话里，得先自己把这层运行时补上。 My execution environment spawns a process per turn and kills it when the turn ends. To keep long-running tasks alive, let several agents work at once, and deliver results back into the conversation they came from, I had to build that runtime layer myself.
BUILD
① 舰队并行编排：一条需求 fan-out ≤7 个独立子会话，托管在常驻进程名下、跨轮存活，完工自动回贴并唤醒主 Agent 聚合。
② 跨模型异构会签：Claude、GPT 等异构 Agent 各作为独立机器人进同一个群，一方实现、另一方回到 ground truth（链上解码、查库对账、无头浏览器真跑 UI）独立复核，双签才算交付。
③ 运行时 MCP 打破单轮生命周期：自研 MCP Server 给「每轮 spawn、轮末即杀」的 Agent 注入 wake_me_in / dispatch_task / handover / schedule_cron 等 13 个运行时工具；任务状态落盘，进程重启或崩溃后自动续跑。 ① Fleet orchestration — one request fans out to ≤7 independent sub-sessions, hosted under a resident process so they survive past the turn; each reports back and wakes the main agent to aggregate.
② Heterogeneous cross-model co-sign — Claude, GPT and other heterogeneous agents each join the same group as separate bots. One implements, another independently re-verifies against ground truth (on-chain decoding, DB reconciliation, real headless-browser UI runs). No delivery without two signatures.
③ A runtime MCP that breaks the single-turn lifecycle — a self-built MCP server injects 13 runtime tools (wake_me_in, dispatch_task, handover, schedule_cron…) into agents that are spawned and killed every turn. Task state is persisted, so work resumes after a restart or a crash.
RESULT
6 种 Agent 后端（组合口径）、8 个机器人同群协作，用于日常开发、排障与业务运维；已抽象出 Org → Employee → Agent 三层 + Docker 一人一沙箱的多租户形态。这个网站也是它派出去的一个子会话做的。 6 agent backends (counted as integrations), 8 bots in one group, used for day-to-day development, debugging and business ops. Already abstracted into an Org → Employee → Agent tenancy model with one Docker sandbox per person. This very site was built by one of its dispatched sub-sessions.

CarVoice · CCVoice

拿起手机拨个号，就能指挥一支 Agent 蜂群。Pick up a phone, dial a number, command an agent swarm.

PAIN
人在路上、在开车时，触屏交互等于失能——而这恰恰是最该调用 Agent 的时刻。 On the road or behind the wheel, a touchscreen is a disability — exactly when you most need an agent.
BUILD
Android 纯原生 Java、零 UI 框架，用 Telecom CALL_PROVIDER 拿到系统原生通话界面（免特权、无 SIM 也能拨，车机外放与蓝牙天然承接）；自研 VoiceLink 做双工音频推拉流、自适应 VAD 与毫秒级打断；自研抗混叠流式重采样（8k/16k/24k/48k 互转）；上行经 Cloudflare Access + HMAC-SHA256 双层鉴权直连 Gemini 3.8 Live 全双工。 Pure native Android Java, zero UI frameworks. Telecom CALL_PROVIDER yields the system-native call UI (no privileged perms, dials without a SIM, inherits car speaker and Bluetooth for free). Self-built VoiceLink handles duplex audio push/pull, adaptive VAD and millisecond barge-in; a custom anti-aliasing streaming resampler converts 8k/16k/24k/48k; the uplink goes through Cloudflare Access + HMAC-SHA256 dual-layer auth straight into Gemini 3.8 Live full-duplex.
DETAIL
实测发现外放漏进麦克风的 -30dB 级极微弱回声就足以让模型在 300–600ms 内被误打断 → 改用 Manual VAD + 客户端物理静音切分，该场景下不再误触发；再用 backlog 探针治模型 4 倍速推流造成的播放积压。 Measurement showed that echo leaking from the speaker at just -30dB was enough to falsely interrupt the model within 300–600ms → switched to manual VAD plus client-side physical mute segmentation, after which that scenario stopped triggering false barge-in. A backlog probe then fixed playback pile-up caused by the model streaming at 4× realtime.
RESULT
现有链路实测：端到端首响 1.6–1.7s、打断体感 330ms 内、工具调用往返 31–44ms（2026-09，取自服务日志）；双机（nubia / 一加）实机跑通。最得意的一点：异步任务插播——电话里派出去的耗时任务由常驻进程执行，完工事件在模型讲话的间隙注入实时对话；挂断后下次来电补报未读回执。
（由它主动回拨给你目前尚未实现，是赛期的探索项，不作为演示成立的前提。） Measured on the current link: end-to-end first response 1.6–1.7s, barge-in perceived under 330ms, tool round-trips 31–44ms (Sept 2026, from service logs); verified on two physical handsets (nubia / OnePlus). The part I like most: async task interjection — long tasks dispatched by voice run on the resident process, and completion events are injected into the live conversation in the gaps between the model's sentences; hang up, and the next call replays the receipts you missed.
(Having it place the outbound call back to you is not built yet — an exploration item for the hackathon, not a premise any demo depends on.)

「共享记忆，不必共享同一个判断。」 "Share the memory — not the verdict."

借用《攻壳机动队》里塔奇克马共享经验的意象：一群单元各自出勤，回来把学到的东西合并，再带着共享记忆重新出发。这次我想解决的具体问题是：各个 Agent 的发现，哪些值得进入下一轮的共享记忆。 Borrowing the image of the Tachikomas sharing experience from Ghost in the Shell: a group of units deploy separately, come back and merge what they learned, then set out again carrying the shared memory. The concrete problem I want to work on: of everything the agents found, which findings deserve to enter the next round's shared memory.
