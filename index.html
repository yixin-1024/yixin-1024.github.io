后端 / 全栈工程师。这两年在做 Agent 系统。

我关心的是同一件事的不同侧面：一个 Agent 说它做完了，凭什么信它？

所以我做的东西大多长这样——把任务派出去、让它跨进程活下来、干完能把结果送回来，然后由另一个模型回到数据库或页面里独立查一遍。这套东西我每天在用，也用它做过合规筛查、开户、发卡和对账这类不能出错的活。

作品

  • cc-lark开源 · Python

    把 IM 群聊当成 Agent 的工作台。一条需求可以派出多个独立子任务并行跑，主会话这一轮结束了它们还活着，完工自动把结果贴回原话题。也支持让不同厂商的模型互相复核——一个实现，另一个回到真实环境查证。

  • CarVoice

    用手机系统自带的拨号器打给 Agent。拨号进去就是原生通话界面，用说的派任务；跑完了结果会在通话中插播，先挂断的话，下次来电补报。Android 原生音频链路自己写的，双工、打断、重采样都在里面。

  • 合规与支付场景的自动化工作项目

    在一家持牌跨境支付平台，把原本跨部门人工周转的流程做成了群里一句话触发的自执行流水线：反洗钱筛查、多币种账户开立、虚拟卡发行、账目双向对账。另外做过聊天记账与多币种复式账本。

  • 更早

    嵌入式（Wi-Fi 6 芯片协议栈、固件与系统级测试）、企业级 IM 的微服务链路、几个 Web3 产品（预测市场的撮合与做市、双链社交应用、一个稳定币协议）。
