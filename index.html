后端 / 全栈工程师

最近在折腾的东西是给 agent 打电话。手机拨 8888，进的就是系统自带的通话界面，然后说你要它干什么。活干完的时候你要还在线，它会在通话里插播结果；等不及先挂了也行，下次打进来听补报。

不过它还不会主动打回来。挂断以后，得你自己再拨一次。

听着像个玩具，做起来全是脏活。车里开免提，它说到一半会突然噤声——查了很久，是外放漏回麦克风的那点回声，只有 -30dB，微弱到我自己都听不见，它却当成有人插话，三百毫秒内把自己掐了。

平时做的大多是这类事：让 agent 把活干完，并且能证明自己真干完了。任务派出去要能跨进程活着，完事把结果送回来，再换一家厂商的模型回数据库里独立查一遍。也拿它跑过反洗钱筛查、开户、发卡和对账——那种地方，「我做完了」这句话本身不算数。

正在做

TACHIKOMAEvoTavern 深圳 · 9 月

几个 agent 各自干完一件事之后，哪些发现值得留给下一轮？我想让每条经验都带着来源接受验证，有冲突先挂起、不投票表决，写进去的还能撤回；最后拿同一个任务跑一遍对照，看它下一轮的行为有没有真的变。

调度、独立复核、语音入口这些是现成的；记忆合并那套机制现在还不存在，是去现场要做的。

作品

  • cc-lark开源 · Python

    把 IM 群聊当成 Agent 的工作台。一条需求可以派出多个独立子任务并行跑，主会话这一轮结束了它们还活着，完工自动把结果贴回原话题。也支持让不同厂商的模型互相复核——一个实现，另一个回到真实环境查证。

  • CarVoice

    用手机系统自带的拨号器打给 Agent。拨号进去就是原生通话界面，用说的派任务；跑完了结果会在通话中插播，先挂断的话，下次来电补报。Android 原生音频链路自己写的，双工、打断、重采样都在里面。

  • 合规与支付场景的自动化工作项目

    在一家持牌跨境支付平台，把以前要跨好几个部门来回传的流程，做成了在群里说一句话就能跑完的：反洗钱筛查、多币种账户开立、虚拟卡发行、账目双向对账。另外做过聊天记账和多币种复式账本。

  • 更早

    嵌入式（Wi-Fi 6 芯片协议栈、固件与系统级测试）、企业级 IM 的微服务链路、几个 Web3 产品（预测市场的撮合与做市、双链社交应用、一个稳定币协议）。
